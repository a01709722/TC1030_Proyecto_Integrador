# TC1030_Proyecto_Integrador
Este proyecto modela la operación básica de un hospital que administra pacientes, doctores y pisos especializados. El hospital cuenta con tres pisos: Emergencia, Observación y Consulta, cada uno con 5 cuartos y un doctor asignado. Cuando un paciente ingresa al hospital, el sistema lo asigna automáticamente al piso correcto según su estatus médico. Cada piso maneja al paciente de forma distinta: emergencia establece un nivel de alerta, observación registra horas de estancia, y consulta asigna un turno de atención. 
# Funcionalidad 
El programa permite agergar pacientes al hospital, quienes son asignados automáticamente al piso que corresponde a su estatus médico ("emergencia", "observación", "consulta"). También permite asignar un doctor a cada piso, liberar pacientes de sus cuartos cuando son dados de alta, y mostrar la información de cualquier paciente, doctor o del estado general del hospital. Todo corre en consola con menú de opciones. 
# Estructura de Clases
EL proyecto usa seis clases. Paciente y Doctor son entidades independientes que almacenan los datos de cada persona. Piso es una clase abstracta que define el comportamiento común de los tres pisos pero no puede instanciarse directamente. De ella heredan PisoEmergencia, PisoObservacion, PisoConsulta, cada uno con su propio comportamiento al ingresar y liberar pacientes. Finalmente, Hospital contiene los tres pisos como un arreglo de punteros , lo que permite aprovechar el polimorfismo al llamar métodos virtuales sobre cualquier piso sin conocer su tipo exacto en tiempo de compliación. 
# Casos en donde el programa no funciona
El sistema no puede ingresar un paciente cuyo estatus sea distinto de los mencionados anteriormente, ya que no sabría a que piso asignarlo. Si los cinco cuartos de un piso están ocupados, el sistema avisa que no hay espacio disponible pero no reasigna al paciente a otro piso automáticamente. Si se intenta liberar un número de cuarto que no pertenece al piso indicado, el sistema no realiza ninguna acción. Si un piso no tiene doctor asignado, los pacientes pueden ingresar de todas formas, pero no habrá médico responsable. El programa no valida nombres vacíos, por lo que ingresar cadenas vacías genera registros incompletos. Todos los datos se pierden al cerrar el programa ya que no hay persistencia en archivos. Si el sistema no puede reservar memoria para un nuevo objeto, el programa puede terminar de forma inesperada al no implementarse manejo de excepciones. Finalmente, el sistema modela un único hospital con exactamente tres pisos fijos y no soporta agregar más pisos ni instancias adicionales.
